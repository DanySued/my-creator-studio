Section 1

What is this app?

My Creator Studio is a personal content dashboard — one login, three tools for producing and publishing Instagram content.

🎠
Carousel Generator

Upload a PDF or Word file — AI turns it into Instagram carousel slides automatically.

🎬
Reel Generator

Enter keywords, pick a song — the app sources stock clips, edits them, and outputs a ready-to-post Reel.

🤖
Instagram Automation

Schedule posts, auto-reply to comments, track followers, and run growth actions — on autopilot.

Think of it like…

A personal content studio. You supply the raw idea; the app produces finished, publishable content.

Section 2

The big picture — how the pieces connect

The app is a collection of specialized services, each doing one job, connected over the internet.

City Analogy

Vercel = the main street (what you see). Railway = the factory (where work happens). Supabase = the filing cabinet + warehouse (data & files). Upstash Redis = a fast sticky-note board (temporary info). Upstash QStash = an appointment book (scheduled posts). GitHub = the master blueprint everything is built from.

Section 3

Every service explained in plain English

📁 GitHub — The Blueprint Archive

GitHub stores all the source code with full version history — you can always roll back if something breaks. It also triggers deployments: pushing new code automatically tells Vercel and Railway to update themselves (Continuous Deployment).

Real-world analogy

The blueprint office. When the architect updates the plans, the construction teams (Vercel, Railway) are automatically notified and rebuild.

🌐 Vercel — The Storefront (What You See)

Vercel hosts the visual interface — every page, button, and form. It delivers these instantly worldwide via a global CDN. It also acts as a secure gatekeeper: when you click "Generate Carousel," Vercel validates the request before forwarding it to Railway.

Real-world analogy

The restaurant's dining room and waitstaff. It looks great and takes your order — but the cooking happens in the kitchen (Railway).

Why Vercel? The app uses Next.js, a framework made by the same company. Deploying takes ~5 minutes with zero configuration.

⚙️ Railway — The Engine Room (Where Work Happens)

Railway runs the Python code that does all the heavy lifting:

  • Calling Google Gemini AI to generate carousel content
  • Downloading stock clips from Pexels and assembling Reels with ffmpeg
  • Posting to Instagram and running automation rules

It runs inside a Docker container — a self-contained mini-computer with Python, ffmpeg, and all libraries pre-installed, so it works identically everywhere.

Real-world analogy

The kitchen. Chefs receive orders from the waitstaff (Vercel), cook the food (process videos, call AI, post to Instagram), and send results back.

Why Railway and not Vercel for this? ffmpeg needs minutes of CPU time. Vercel only supports short, fast operations — not video processing.

🗄️ Supabase — The Filing Cabinet + Warehouse

Supabase provides two things: a database and a file storage system.

The Database (Filing Cabinet)

All structured data lives here — Instagram accounts, scheduled posts, carousel history, automation rules, activity logs, and more. Organized into tables, like spreadsheet tabs.

The Storage (Warehouse)

Large files live in three separate folders (buckets):

🎵
uploads/

Audio files and images you upload

🎥
generated/

Finished MP4 Reel files

🎼
music/

Background music tracks for Reels

Real-world analogy

A filing cabinet (database — organized text records) combined with a storage warehouse (storage — the actual large files).

⚡ Upstash Redis — The Fast Sticky-Note Board

Redis stores data in RAM instead of on disk — thousands of times faster than a regular database, but temporary. Used for two things:

1
Reel job progress

While ffmpeg processes your video, a progress percentage updates many times per second. Redis handles this speed; the main database cannot.

2
Instagram rate-limit counters

Instagram caps automated actions (e.g. 100 follows/day). Redis tracks a counter per account that resets every 24 hours, preventing bans.

Real-world analogy

A kitchen whiteboard showing live order status. Fast and current — not for permanent records. Wiped clean at the end of the night.

📅 Upstash QStash — The Appointment Book

QStash remembers to do something at a specific future time — and guarantees it happens even if the app restarts in between. When you schedule a post for 3 PM, QStash stores the appointment on its own servers and fires a signal to Railway at exactly that time.

Why not an internal timer? The old solution (APScheduler) stored jobs in Railway's memory. Every code update restarts Railway — silently deleting all pending posts. QStash stores appointments externally, so they survive any restart.

Real-world analogy

A cloud alarm service. Even if you throw your phone in the river, the alarm still rings at 3 PM — because it lives in the cloud, not on your device.

Section 4

How your actions travel through the system

What happens behind the scenes for each core feature.

Generating a Carousel

1
You upload a PDF or Word document

Your browser extracts all the text locally — no server involved yet.

2
You click "Generate Slides"

Vercel forwards the text + settings (slide count, theme) to Railway.

3
Railway calls Google Gemini AI

Gemini returns structured JSON: slide titles and bullet points.

4
Railway saves to Supabase and returns the result

Slide data is stored in your history and sent back to the browser.

5
Your browser renders and exports the slides

Preview appears. On Export, the app generates PNGs and zips them for download — all inside your browser.

Generating a Reel

1
You enter keywords, pick audio, and click "Generate"

Railway creates a job in Supabase (status: "queued") and returns a job ID immediately — without waiting for the video.

2
Railway processes the video in the background

Searches Pexels for clips, downloads and trims them, scales to 1080×1920, mixes audio, burns text overlay.

3
Your browser polls every 2 seconds

Railway reads the progress percentage from Upstash Redis and returns it. The progress bar updates in real time.

4
Railway uploads the finished MP4 to Supabase Storage

Saved to the "generated" bucket. Database record updated to "done."

5
You click Download

Railway issues a 60-minute secure link to the file in Supabase Storage. Your browser downloads directly from Supabase's CDN.

Scheduling an Instagram Post

1
You pick media, write a caption, choose a date/time, and click "Schedule"

Vercel sends the details to Railway.

2
Railway saves the post to Supabase (status: "pending")

Then registers the appointment with QStash: "call me back at [scheduled time] with this post ID."

3
At the scheduled time, QStash signals Railway

QStash calls Railway's webhook URL: "it's time to post [post ID]."

4
Railway executes the post

Retrieves details from Supabase, authenticates with Instagram, publishes. Status updated to "posted."

Section 5

Where your data lives

Every piece of information has a specific home:

🗄️
Supabase Database
Permanent structured records

Carousel history · Reel history · Instagram accounts · Scheduled posts · Automation rules · Follower snapshots · Activity logs · Daily counters

📦
Supabase Storage
Large files

Generated MP4 Reels · Uploaded audio · Uploaded images

⚡
Upstash Redis
Fast temporary data

Reel job progress · Instagram daily action counters (resets at midnight) · Short-lived cache

📅
Upstash QStash
Scheduled job queue

Future Instagram post appointments — held externally so they survive server restarts

Instagram credentials are stored only in Supabase, encrypted at rest — never logged or stored in plain text.

Section 6

The deployment plan — step by step

Taking the app from your local computer to live on the internet, in order:

Phase 0
Gather all credentials

Nothing else can be configured without these keys.

  • Create a Supabase project — copy the database URL, project URL, and service key
  • Create three storage buckets: uploads, generated, music
  • Copy QStash token and signing keys from the Upstash console
  • Connect the GitHub repo to both Railway and Vercel
Phase 1
Migrate the database — SQLite → PostgreSQL

SQLite works locally but can't run on Railway. Supabase provides production-grade PostgreSQL.

  • Update the connection code to use Supabase's connection string
  • Add the PostgreSQL driver to the dependency list
  • Verify all 12 database tables are created correctly on Supabase
Phase 2
Move file storage to Supabase

Railway's disk is wiped on every deployment — files must live in Supabase to persist.

  • After video processing, upload the MP4 to the generated bucket instead of local disk
  • Serve downloads as temporary secure links from Supabase (not direct server transfers)
  • Do the same for audio uploads — remove the local media server
Phase 3
Connect QStash for scheduled posts

Replace the in-memory scheduler (loses jobs on restart) with QStash (stores jobs externally, guarantees delivery).

  • Register post appointments with QStash instead of the internal timer
  • Add a webhook endpoint that QStash calls when it's time to post
  • Add signature verification so only genuine QStash calls are accepted
Phase 4
Prepare a production server configuration

The current setup runs in development mode — slower and wasteful in production.

  • Create a production server config (strip dev-only features)
  • Update the allowed-origins whitelist to include the production domain
  • Add a health check endpoint so Railway knows when the app is ready
Phase 5
Deploy the backend to Railway

The Python engine room goes live.

  • Add all secret keys (Supabase, Gemini, Pexels, Instagram, Upstash, QStash) as private env vars in Railway
  • Trigger the first deployment — Railway builds the Docker container and starts the server
  • Verify the health check passes and copy the Railway URL
Phase 6
Deploy the frontend to Vercel

The visual storefront goes live.

  • Add the Railway URL as API_URL in Vercel's env vars
  • Trigger deployment — confirm Gemini and Pexels health checks pass
  • Add the Vercel URL to Railway's allowed origins, then redeploy Railway
Phase 7
Set up automatic deployments (CI/CD)

Every future code push deploys automatically.

  • Create a GitHub Actions workflow: on push to main, run checks then deploy to Railway and Vercel
  • Store all secret keys in GitHub's encrypted secrets for the workflow to use
Section 7

Glossary of technical words

Every technical term used in this document, in plain English.

API (Application Programming Interface)

A contract between two programs — it defines what one can ask the other to do, like a restaurant menu.

CDN (Content Delivery Network)

A global network of servers that cache your app's files. Users are served from the nearest location, making the app faster everywhere.

Container / Docker

A self-contained package bundling an app with everything it needs to run. Works identically on any machine — no "it works on my computer" surprises.

Database

An organized system for storing and retrieving information — like a very fast spreadsheet that many programs can read and write simultaneously.

Deployment

Moving code from a developer's computer onto a server so users on the internet can access it.

Environment Variables

Secret settings (API keys, passwords) kept separate from the code so they're never accidentally shared publicly.

ffmpeg

Open-source software that cuts, resizes, combines, and encodes video and audio — the engine behind Reel generation.

PostgreSQL / SQLite

Two database types. SQLite is a single-file database — simple, great for one computer. PostgreSQL is a full server database built for production with many simultaneous users.

Redis

A database that stores everything in RAM — much faster than disk, but temporary. Used for speed, not permanence.

Webhook

A URL that receives automated messages from other services. When QStash is ready to trigger a scheduled post, it "rings" the webhook and the app answers.

CI/CD (Continuous Integration / Continuous Deployment)

An automated pipeline that checks and deploys code whenever you push an update — no manual steps needed.
